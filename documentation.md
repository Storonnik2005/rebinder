# Документация системы резервного копирования (boo.cpp)

## Общее описание
Система представляет собой реализацию механизма резервного копирования файлов с поддержкой различных стратегий хранения. Написана на C++ с использованием современных практик программирования.

## Системные требования
- Операционная система: Windows
- Компилятор с поддержкой C++11 или выше
- Библиотеки:
  - iostream - для операций ввода-вывода
  - vector - для работы с динамическими массивами
  - string - для работы со строками
  - memory - для работы с умными указателями
  - fstream - для файлового ввода-вывода
  - ctime - для работы с датой и временем
  - direct.h - для работы с директориями в Windows
  - io.h - для низкоуровневого ввода-вывода
  - algorithm - для алгоритмов обработки данных
  - locale - для работы с локализацией
  - windows.h - для доступа к Windows API

## Применение принципов GRASP

### 1. Creator (Создатель)
- Реализован в классе `BackupJob`, который создает экземпляры `RestorePoint`
- `BackupRepository` отвечает за создание структуры хранилища

### 2. Information Expert (Информационный эксперт)  
- `FileBackupObject` содержит всю информацию о файле и отвечает за операции с ним
- `RestorePoint` управляет информацией о точке восстановления

### 3. Low Coupling (Низкая связанность)
- Использование интерфейсов `BackupObject` и `StorageAlgorithm` уменьшает зависимости
- Классы взаимодействуют через абстрактные интерфейсы

### 4. High Cohesion (Высокая связность)
- Каждый класс имеет четко определенную зону ответственности
- `FileBackupObject` работает только с файлами
- `StorageAlgorithm` отвечает только за стратегию хранения

### 5. Controller (Контроллер)
- `BackupJob` выступает контроллером, координируя процесс резервного копирования
- Управляет созданием точек восстановления и применением стратегий

### 6. Pure Fabrication (Чистая выдумка)
- `BackupRepository` - служебный класс для работы с хранилищем
- Не представляет реальную предметную область, но улучшает организацию кода

### 7. Protected Variations (Защита от изменений)
- Интерфейс `StorageAlgorithm` позволяет легко добавлять новые стратегии хранения
- `BackupObject` обеспечивает расширяемость для новых типов объектов

### 8. Polymorphism (Полиморфизм)
- Использование виртуальных методов в интерфейсах
- Разные реализации стратегий хранения через общий интерфейс

### 9. Indirection (Посредник)
- `BackupRepository` выступает посредником между `BackupJob` и файловой системой
- Уменьшает прямые зависимости между компонентами


## Основные компоненты

### 1. Интерфейсы
#### BackupObject
- Абстрактный класс для объектов резервного копирования
- Методы:
  - `getPath()` - получение пути к объекту
  - `getName()` - получение имени объекта
  - `getSize()` - получение размера объекта
  - `exists()` - проверка существования объекта

#### StorageAlgorithm
- Абстрактный класс для стратегий хранения
- Методы:
  - `store()` - сохранение объектов резервного копирования

### 2. Реализации

#### FileBackupObject
- Реализация BackupObject для работы с файлами
- Функционал:
  - Работа с конкретными файлами в файловой системе
  - Получение метаданных файла

#### Стратегии хранения:
1. **SplitStorageAlgorithm**
   - Каждый объект хранится в отдельной директории
   - Создает иерархическую структуру хранения

2. **SingleStorageAlgorithm**
   - Все объекты хранятся в общей директории
   - Упрощенная структура хранения

### 3. Основные классы

#### RestorePoint
- Представляет точку восстановления
- Хранит:
  - Имя точки
  - Время создания
  - Список объектов

#### BackupRepository
- Управляет хранилищем резервных копий
- Отвечает за:
  - Создание и проверку директории хранилища
  - Предоставление пути к хранилищу

#### BackupJob
- Основной класс для управления процессом резервного копирования
- Функционал:
  - Добавление/удаление объектов
  - Создание точек восстановления
  - Смена алгоритма хранения
  - Вывод информации о состоянии

#### BackupObjectFactory
- Фабрика для создания объектов резервного копирования
- Методы:
  - `createFileBackupObject()` - создание объекта для работы с файлами

## Использование

### Пример базового использования:
```cpp
// Создание репозитория
auto repository = std::make_shared<BackupRepository>(".\\backup_repository");

// Выбор стратегии хранения
auto splitStorage = std::make_shared<SplitStorageAlgorithm>();

// Создание джобы
auto backupJob = std::make_shared<BackupJob>("DocumentsBackup", splitStorage, repository);

// Добавление файлов
auto fileObject = BackupObjectFactory::createFileBackupObject("path/to/file.txt");
backupJob->addBackupObject(fileObject);

// Создание точки восстановления
backupJob->createRestorePoint("BackupPoint1");
```

  - Возможность создания директорий
  - Корректность операций копирования
